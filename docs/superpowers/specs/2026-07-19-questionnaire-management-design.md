# 新版问卷管理与版本化答卷系统设计说明

## 1. 目标与约束

本设计在不破坏现有问卷提交、用户画像和网站推荐能力的前提下建设新版问卷系统。实施顺序为先完成新的数据结构、后台管理页面和接口，再以受控范围验证新版普通用户入口，完成数据迁移与兼容读取后才切换全部用户。开发期间旧问卷持续可用；新旧系统并行，并保留可回退能力。

本次设计仅定义新版问卷管理、答卷、版本化、数据治理及其与现有画像和推荐的衔接，不包含生产实现、部署改动、推荐算法重写或旧接口的直接删除。

## 2. 功能范围

新版系统包含：问卷答卷管理、题目和选项管理、问卷版本管理、职业字典管理、草稿及自动保存、历史答卷、用户数据导出和删除申请、普通管理员与超级管理员权限、问卷统计，以及与既有用户画像和推荐系统的兼容衔接。

本期明确不包含：多层嵌套或复杂逻辑表达式、任意脚本题型、文件上传题、随机分流或 A/B 测试、AI 自动生成题目、直接删除旧问卷接口和部署相关修改。

## 3. 用户类型与职业字典

固定用户类型为学生、在职个人、企业/组织用户。用户在填写前选择用户类型和职业。

系统提供固定职业字典；管理员可新增职业。职业名称全局唯一，每项职业具有稳定内部编码、所属大类、排序值和启用状态。新职业须选择“使用通用问卷”或“暂不开放”。已被答卷使用的职业不得物理删除，只可停用。停用职业不再出现在新用户问卷中，但历史答卷必须持续正常展示其快照信息。

## 4. 问卷匹配与版本锁定

问卷按以下优先级匹配，找到第一个已发布且生效的版本后立即停止：

1. 职业与用户类型组合版本。
2. 职业专属版本。
3. 用户类型专属版本。
4. 通用版本。

同一适用范围、同一时间仅允许一个当前生效版本。首次建立草稿时锁定匹配到的版本；之后发布新版不会改变已有草稿。没有专属版本时按上述回退顺序使用通用问卷。

## 5. 问卷定义与版本生命周期

问卷定义用于承载业务逻辑名称、适用范围和管理归属；每次可编辑内容均位于独立版本。版本状态至少包括草稿、已发布、已停用和已归档。

管理员只能编辑草稿版本。已发布版本不可直接编辑；修改时必须复制生成新草稿。发布后，新打开问卷的用户使用新版，已经开始填写的用户继续完成原锁定版本。历史答卷永久绑定提交时的版本。

回滚不直接激活旧版本：管理员复制目标旧版本的内容为一个新草稿，重新预览、执行检查并发布。每个版本保留版本号、版本说明、来源版本、创建人、发布人、创建时间和发布时间。

## 6. 题目、选项与不可变快照

支持单选题、多选题和简答题。每道题包含标题、说明、题型、必填状态、排序、启用状态、是否通用题、条件显示规则和所属问卷版本。

多选题配置最少和最多选择数量，且最小值不得大于最大值、最大值不得超过启用选项数。简答题配置正整数的最大字数。选项包含显示名称、稳定内部值、排序和启用状态。

没有任何答卷引用的草稿题目和选项可以删除；被历史答卷引用后不得物理删除，只能停用。已发布版本与正式答卷均保存题目和选项快照，历史展示不得依赖后来被修改的当前文本，必须保留提交时题文、选项文和内部值。

## 7. 简单条件显示

仅支持前置单选题选择某选项，或前置多选题包含某选项时显示后续题目。规则不得多层嵌套，不支持复杂与、或、非组合，不得引用后面的题目，也不得引用不存在或已停用的题目。

隐藏题的答案不参与提交；前置答案变化导致题目隐藏时，系统自动清除该题答案。前端渲染与后端提交校验共同执行同一规则。历史答卷依据其提交版本当时的规则解释和展示。

## 8. 草稿与自动保存

用户首次打开匹配问卷时创建服务端草稿。同一用户最多一份进行中草稿，草稿保存用户类型、职业、锁定版本和答案。用户停止操作 1 秒后自动保存，页面显示“正在编辑、保存中、已保存、保存失败”状态；网络恢复后自动重试最近一次未保存数据。跨设备登录后可继续填写，正式提交前必须等待保存完成。

未提交草稿不影响用户画像或推荐。草稿在最后一次编辑后 30 天过期；普通用户不能继续填写，重新进入时按当前最新匹配版本创建或恢复可用流程。过期草稿后台保留 90 天后自动清理。清理日志只记录数量、时间和结果，绝不记录被清理的答案。

## 9. 修改职业或用户类型

用户变更职业或用户类型须二次确认。确认后保留通用题答案，清除不再适用的职业专属、用户类型专属和组合专属题答案；在新旧版本中仍存在且选项兼容的答案可以保留。系统重新执行版本匹配，将草稿绑定至新版本并自动保存。

正式提交前，原当前有效答卷继续驱动推荐；变更草稿不得提前改变画像或推荐结果。

## 10. 正式提交、历史答卷与重填

每次正式提交都生成新的正式答卷，绝不覆盖旧答卷。新答卷成为当前有效答卷，旧答卷标记为历史；用户画像和推荐只读取当前有效答卷。用户重新填写期间，原有效答卷持续生效，只有新答卷提交成功后才切换画像。

历史答卷不可修改、删除或恢复为当前答卷。普通用户可在个人中心查看自己的当前和历史答卷。用户可主动重填，点击后需二次确认；同一时间只允许一份重填草稿。管理员也可允许某用户重填，但不删除历史答卷。用户可放弃草稿，后续重新进入时按当前最新匹配版本开始。

## 11. 后台答卷管理

后台主入口为 `/admin/questionnaires`，建议包含答卷列表、答卷详情、草稿列表、过期草稿、问卷统计和数据删除申请标签页。答卷列表支持用户搜索、职业筛选、用户类型筛选、问卷版本筛选、当前有效/历史状态筛选、提交时间筛选、分页以及空、加载和错误状态。

管理员不能直接修改或删除用户正式答卷；仅可查看、允许用户重填和处理数据删除申请。后台详情中的展示内容按权限进行脱敏。

## 12. 管理员权限与审计

普通管理员可管理职业字典、创建和编辑草稿版本、管理题目和选项、配置条件、预览、查看统计、查看脱敏答卷和处理其职责范围内的申请；不得发布或停用版本，也不得查看完整敏感答卷。

超级管理员拥有发布、停用、创建回滚草稿、查看完整答卷和审核数据删除申请的权限。查看完整答卷必须填写访问原因，并写入审计日志。所有敏感后台操作记录操作者、时间、目标、动作、原因、结果和必要的前后状态摘要；日志不记录密码、Token、Secret 或数据库异常详情。

## 13. 发布检查与并发发布

发布前执行结构化检查：适用范围完整且无冲突、版本状态允许发布、题目顺序有效、题目标题和题型完整、必填与长度/选项约束有效、条件引用合法、条件目标位于前面、选项稳定值唯一、同范围当前生效版本冲突可处理，以及预览可渲染。警告需要超级管理员明确确认，错误必须修复后才可发布。

发布操作在事务中完成：同适用范围旧生效版本停用、新版本生效、发布信息和检查结果落库。两个超级管理员同时发布同一范围时只能成功一个，其余请求返回可识别的发布冲突。

## 14. 用户数据导出与删除申请

用户可导出本人问卷数据，包括当前和历史正式答卷、版本信息、题目与选项快照、提交时间及申请状态；导出不得包含其他用户数据或任何敏感配置。用户可提交删除申请并查看状态。

删除申请经审核通过后，以事务完成匿名化：解除答卷与用户账户的身份关联，清除姓名、邮箱、手机号、用户 ID 等身份字段，保留匿名职业、用户类型、兴趣等统计数据，删除未提交和过期草稿。账户、收藏和登录能力保留；推荐恢复通用推荐，用户状态恢复为未填写问卷，用户可以立即重新填写。匿名化后原答卷不可恢复，且不等同于账号注销。

## 15. 统计与推荐系统衔接

统计按职业、用户类型、问卷版本、提交时间、题目和选项聚合，默认仅使用未匿名化或可依法保留的匿名化统计快照，不暴露个人身份信息。管理页应提供筛选、空、加载和错误状态。

开发期现有推荐系统保持不变。正式切换后，新系统仅在正式答卷提交成功时提供用户画像；草稿绝不影响推荐。推荐仅读取当前有效答卷，删除或匿名化后使用通用推荐。通过兼容层把新版答卷转换为当前推荐服务所需结构，不重写第二套推荐算法。

## 16. 建议数据模型

以下表使用明确外键或稳定业务 ID，统一包含必要的创建与更新时间；具体索引和字段类型在实现计划中按现有数据库方言确定。

| 表 | 主要职责 |
| --- | --- |
| `questionnaire_definitions` | 问卷逻辑定义、名称及适用范围。 |
| `questionnaire_versions` | 版本号、状态、来源版本、发布与创建信息。 |
| `questionnaire_questions` | 版本内题目快照、排序、约束和启用状态。 |
| `questionnaire_options` | 题目选项快照、稳定值、排序和启用状态。 |
| `questionnaire_conditions` | 简单条件显示规则。 |
| `occupations` | 职业字典、编码、分类、排序和启停状态。 |
| `questionnaire_drafts` | 用户进行中草稿、锁定版本、有效期和乐观锁版本。 |
| `questionnaire_draft_answers` | 草稿答案。 |
| `questionnaire_responses` | 正式答卷主记录、当前有效/历史状态及匿名化状态。 |
| `questionnaire_response_answers` | 正式答卷的题目、选项和答案快照。 |
| `questionnaire_publish_checks` | 发布检查结果、警告确认和执行人。 |
| `questionnaire_data_requests` | 数据导出与删除申请及审批状态。 |
| `questionnaire_audit_logs` | 敏感后台操作审计。 |

已发布版本与正式答卷一律使用快照，不能依赖可变题目文本。历史正式答卷不直接删除；匿名化后断开用户关联。每用户当前有效答卷、每用户进行中草稿分别由唯一约束或等效事务保证最多一条。

## 17. 普通用户接口组

接口按当前认证体系鉴权，建议提供：获取用户类型与职业列表；创建或恢复草稿；切换职业或用户类型并重新匹配版本；自动保存草稿；获取草稿；放弃草稿；提交答卷；查看当前答卷；查看历史答卷；主动重填；导出个人问卷数据；提交删除申请；查看删除申请状态。

提交接口必须验证草稿未过期、锁定版本与提交版本一致、条件显示规则、题型约束和幂等键。接口只返回当前请求所需业务错误和安全的展示信息。

## 18. 后台接口组

后台接口建议包括：问卷定义列表；创建草稿版本；复制版本；编辑草稿版本；题目管理；选项管理；排序；条件配置；预览；执行发布检查；发布版本；停用版本；创建回滚草稿；答卷列表；答卷详情；草稿及过期草稿列表；允许用户重填；统计；删除申请列表与审核；超级管理员查看完整答卷；审计日志列表；职业字典管理。

所有后台接口显式执行角色检查和数据范围检查；完整答卷读取要求超级管理员携带访问原因，并在成功或失败时记录审计事件。

## 19. 错误处理与安全边界

未登录返回 401，无管理员权限返回 403，不存在的版本或资源返回 404。过期草稿返回明确业务错误；草稿版本与提交版本不一致时拒绝提交；自动保存使用更新时间或版本号发现冲突；重复提交使用幂等保护；发布冲突在事务层处理。

数据库失败不得产生半提交答卷，且不得向前端暴露数据库异常、连接串、堆栈、密码、Token 或 Secret。前端对保存失败、版本过期、权限不足、加载失败和接口错误提供可理解提示与安全重试入口。

## 20. 并发与事务

草稿自动保存以草稿版本号或 `updated_at` 实现乐观锁。正式提交在单个事务中完成：验证草稿与版本、写入正式答卷及答案快照、将旧有效答卷设为历史、将新答卷设为当前有效、更新兼容层画像数据，并保证整体成功或整体失败。

发布在同一事务中完成旧同范围版本停用和新版本生效。删除申请匿名化在事务中完成。过期草稿清理任务必须可重复执行且幂等，重复运行不得重复破坏数据。

## 21. 兼容与迁移策略

阶段一：建立新表、后台接口和后台管理页面，不修改既有普通用户问卷入口。

阶段二：建设新版普通用户接口和页面，通过功能开关仅向管理员或测试用户开放，既有用户继续使用旧问卷。

阶段三：将旧问卷数据迁移为初始正式答卷，对迁移结果进行数量和字段校验，并为推荐系统增加新版答卷兼容读取。

阶段四：切换普通用户问卷入口，保留旧接口回退能力，观察错误率和提交成功率。

阶段五：稳定后停用旧写入接口，旧数据暂时只读，不立即删除旧表。

## 22. 页面与响应式设计

保持现有后台 UI 风格，不整体重做。新增 `/admin/questionnaires` 作为答卷管理主页，`/admin/questionnaires/builder` 作为问卷配置页，`/admin/questionnaires/versions/:id` 用于版本详情和预览，`/admin/questionnaires/responses/:id` 用于答卷详情。

个人中心增加当前答卷、历史答卷、重新填写、数据导出和删除申请状态。切换阶段的新版用户问卷替换现有 `/questionnaire`，路由尽量保持不变，避免不必要地改动登录流程和路由守卫。

所有新增页面覆盖 1440px、1024px 和 375px；并分别设计加载、空、保存中、保存失败、版本过期、权限不足与接口错误状态。375px 页面不得产生横向溢出。

## 23. 测试策略

后端测试覆盖：匹配优先级、版本锁定、自动保存与乐观锁、30 天过期、过期后 90 天清理、题目校验、条件显示校验、正式提交事务、历史答卷保留、当前有效答卷唯一性、发布检查与权限、回滚草稿、脱敏权限、删除申请与匿名化、推荐兼容层。

前端测试覆盖：动态题目渲染、单选/多选/简答校验、1 秒保存防抖、保存状态、职业与用户类型切换、条件题显示与清空、历史答卷只读、管理员权限、发布预览、响应式布局、刷新恢复和控制台错误。

回归测试覆盖登录、注册、Authing、原问卷、用户画像、推荐接口、收藏、个人中心、其他后台页面、Vite 构建和后端全量测试。

## 24. 验收标准

1. 新系统开发期间旧问卷不受影响。
2. 普通管理员不能发布版本，超级管理员只有通过检查后才能发布。
3. 已发布版本不可直接编辑，回滚必须复制为新草稿。
4. 草稿支持跨设备恢复，停止操作 1 秒后保存，同一用户仅一份进行中草稿。
5. 草稿 30 天后过期，过期后后台保留 90 天再清理。
6. 历史答卷不随题目修改改变；最新正式答卷才用于推荐。
7. 修改职业或用户类型不会保留无效专属答案。
8. 普通管理员只看到脱敏信息；超级管理员查看完整信息必须填写原因。
9. 用户可以导出自身数据，删除申请审核后答卷匿名化而账户保留，并恢复通用推荐和立即重填能力。
10. 375px 无横向溢出，前后端自动化测试通过，所有错误响应均不泄露敏感信息。

## 25. 关键设计决策

先后台后前台可先验证数据模型、权限和发布流程，降低影响所有用户的风险。新旧系统并行但不同时向全体用户开放，保留可验证的渐进迁移和回退窗口。发布版本与正式答卷采用快照，确保审计、历史展示和统计稳定。

自动保存使用 1 秒防抖，在减少请求的同时保持跨设备恢复体验。条件题仅支持简单规则，以保证可配置、可验证和可解释。回滚复制为新版本，保留完整演进链和发布审计。删除采用匿名化，满足用户数据治理且保留合规统计。推荐只读取最新有效答卷；普通管理员使用脱敏数据；本阶段不修改推荐算法。
